The WhatsApp admin is the checkout.

CV Cahaya Pelumasindo publishes 91 products with no prices. Every page ends with one button: Cek Harga dan Ketersediaan — which opens a chat with one of two admins. This agent does not sell. It converts a messy inquiry into a price-ready RFQ, and it is structurally unable to quote a price.

01

Problem

Leak 1

Price is a conversation, not a page

Nothing can be decided without an admin. Every inquiry is a human dependency, so volume cannot grow without headcount.

Leak 2

The inquiry arrives unstructured

A buyer sends "flow meter solar buat pertamina 2 nozzle, budget 15jt". Someone must reconstruct part, quantity, spec, company, city and urgency before anything can be priced. Repeated hundreds of times.

Leak 3

Out of stock is invisible

Availability is unpublished. When a part is unavailable the thread stalls or dies, even though the catalog carries many interchangeable brands.

03

What I built

  • Retrieval is exact-first. Part number, then structured spec filters, then semantic candidates. A semantic hit is never stated as a fitment fact.
  • Fitment is curated, not inferred. Six explicit rules (connection size, pressure with a 10% margin, flow range, fluid, flange, accuracy) evaluated in order; the first failing dimension is reported.
  • Guards run after generation, in code. Currency patterns, stock assertions and compatibility claims are validated on the outbound message and replaced with a safe fallback. Prompts are not a guarantee; this is.
  • The handoff is the product. An RFQ is only emitted with a resolvable item, a quantity and a delivery city. The record is written before the admin message is sent.
  • Availability is a state machine. available | indent | unknown | discontinued with source and timestamp. In manual mode every answer is "perlu dicek ke gudang".
  • Price relay is audited. A price reaches a buyer only after an admin action, and every relay stores admin identity, timestamp, raw message and RFQ id.

  • Admin silence has a deadline. At handoff the buyer is told the expected reply window. If the admin has not answered by then, the buyer receives one honest update, the admin receives one reminder, and the thread stays visible in the pending queue. Nothing is promised twice.
  • After 24 hours the notice switches to a WhatsApp template, because free-form replies are no longer allowed.
05

Limits, stated plainly

What this demo does not prove

  • The catalog is a 24-product demo subset, not the client's 91 products. Real fitment tables need manufacturer datasheets and a named verifier.
  • Availability is manual only. No stock source exists yet, so every availability answer is a warehouse check, never a claim.
  • Demo conversations are recorded replays. The agent runs the same code, but you are watching transcripts, not a live WhatsApp number.
  • Equivalence pairs are seeded at medium confidence, so the agent always labels substitutions "kandidat, perlu konfirmasi teknis".
  • Eval numbers come from the deterministic mock model, not from a frontier model under production traffic.
